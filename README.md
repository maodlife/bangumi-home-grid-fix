# Bangumi 首页跳看进度格子修正

用于修正 Bangumi 首页把“已看总数”误当成连续观看进度的问题。

例如仅标记了《名侦探柯南》第 518、519 话时，原首页会从 `02` 开始显示；启用脚本后会从最高已看正片 `519` 开始显示，并把下一话快捷操作修正为 `ep.520 看过`。

## 安装

1. 在浏览器中安装 Tampermonkey 或 Violentmonkey。
2. 打开 [`bangumi-home-grid-fix.user.js`](./bangumi-home-grid-fix.user.js)，将内容安装为新用户脚本。
3. 登录 `https://bgm.tv/` 并刷新首页。

脚本首版只匹配 `https://bgm.tv/` 首页。

## 使用

- 在首页条目标题旁点击 `[修正格子]`。
- 设置会按条目保存在用户脚本管理器的本地存储中。
- 此后每次加载首页，脚本都会重新读取已启用条目的章节页。
- 点击 `[恢复原始]` 会关闭该条目的修正并刷新首页。
- 读取失败时，原页面保持不变；点击 `[修正失败，重试]` 可重试。

脚本只计算以整数或小数编号开头的正片（例如 `519.`、`12.5.`），忽略 `SP`、`OP`、`ED` 等其他章节类型。

## 工作原理

脚本不修改 Bangumi 账户中保存的连续观看进度，只修正首页的显示和快捷操作：

1. 从首页的条目面板中取得条目 ID。
2. 仅为用户手动启用过的条目请求 `/subject/{id}/ep`。
3. 使用 `DOMParser` 解析返回的完整章节页。
4. 从正片中找出标记为“看过”的最高章节，并将它作为本次页面的显示起点。
5. 复用 Bangumi 已经生成的章节格子和数量，只替换每个格子的章节 ID、链接、标题、编号及状态样式。
6. 将进度摘要改为“已看数量 + 最高已看章节”，并把“下一话看过”快捷操作指向最高已看章节之后的第一话。

以《名探侦柯南》为例，原首页生成了 72 个格子。最高已看正片为 519 时，脚本会把原来的 `02–73` 映射为 `519–590`，不会额外创建格子或改变原版面高度。

选择读取章节 HTML 而不是 Bangumi API，是因为登录后的章节页已经同时包含：

- 每一话的章节 ID、编号和标题；
- 放送状态；
- 当前用户的“看过”状态。

因此不需要申请或保存 API Token。脚本只向当前 `bgm.tv` 域名发起同源读取请求，不会向第三方发送数据。

## 数据与状态规则

- 启用状态以条目 ID 为键，保存在用户脚本管理器的 `GM_setValue` 存储中。
- 每次打开首页都会重新读取已启用条目的章节页，不跨页面缓存观看状态。
- 最高已看正片是当前页面的固定显示锚点。
- 在本页将后续章节标记为“看过”时，脚本会更新颜色、摘要和下一话快捷操作，但不会移动整排格子。
- 再次打开或刷新首页后，脚本才会以新的最高已看章节重新确定起点。
- 如果最高已看章节之后不足原有格子数量，只显示实际存在的正片，其余格子隐藏。
- 如果没有已看正片，不改写格子；启用设置仍然保留。
- 点击 `[恢复原始]` 会删除该条目的启用设置并刷新页面，让 Bangumi 重新生成原始内容。

## 依赖的 Bangumi DOM

脚本依赖以下页面结构。Bangumi 改版后若这些节点或属性变化，应优先检查这里：

| 用途 | 选择器或标记 | 当前假设 |
| --- | --- | --- |
| 首页条目面板 | `#cloumnSubjectInfo .infoWrapper[id^="subjectPanel_"]` | 面板 ID 形如 `subjectPanel_899` |
| 网格列表 | `.epGird ul.prg_list` | 直接子元素 `li` 的数量就是应保留的格子数量 |
| 网格章节链接 | `.prg_list li > a` | 可通过改写 `href`、`id`、`rel`、`subject_id` 继续使用原站交互 |
| 进度快捷操作 | `.header a.prgCheckIn`、`.tinyHeader a.prgCheckIn` | `ep_id` 决定被标记为“看过”的章节 |
| 网格进度摘要 | `.tinyHeader #prgsPercentNum` | 原始格式形如 `[2/??]` |
| 完整模式摘要 | `.header .progress .inner small` | 显示原始连续进度 |
| 首页列表摘要 | `#prgSubjectList a.subjectItem.title small.progress_percent_text` | 原始格式形如 `[2/??]` |
| 章节页正片链接 | `a[href^="/ep/"]` | `href` 最终应匹配 `/ep/{数字 ID}` |
| 章节编号和标题 | 章节链接文本 | 格式形如 `519.标题` 或 `12.5.标题` |
| 已看状态 | 章节所属 `li` 内的 `.statusWatched` | 存在即表示该正片已看 |
| 已放送状态 | 章节所属 `li` 内的 `.epAirStatus .Air` | 决定使用 `epBtnAir` 或 `epBtnNA` 样式 |

`cloumnSubjectInfo` 是 Bangumi 当前页面中的实际 ID 拼写，脚本有意沿用，并非本项目的拼写错误。

## 页面内进度跟踪

脚本改写格子后仍然复用 Bangumi 自带的点击处理。原站在快捷标记成功后可能重新修改进度摘要、快捷操作或格子状态，因此脚本使用 `MutationObserver` 观察当前条目面板。

观察到原站更新后，脚本会：

1. 读取带有 `epBtnWatched` 样式的格子；
2. 对比原站连续进度数字是否增加；
3. 更新本页内存中的观看状态；
4. 再次渲染相同的固定格子范围。

这就是“状态立即更新，但格子起点只在下次刷新时前移”的实现方式。

## 失败与恢复

- 网络错误、HTTP 错误、章节解析失败或首页 DOM 不符合预期时，脚本会恢复启用前保存的元素属性和内容。
- 失败不会修改 Bangumi 账户数据，也不会把连续进度输入框伪装成最高已看话数。
- 错误详情会写入浏览器控制台，同时把控制按钮显示为 `[修正失败，重试]`。
- `episodeRequests` 只在单次页面生命周期内合并同一条目的重复请求；失败的请求会从缓存中移除，允许重试。

## 已知脆弱点

- Bangumi 修改首页或章节页 DOM、CSS 类名、章节链接格式后，解析或原站点击交互可能失效。
- 脚本读取完整章节页；对《名侦探柯南》这类超长条目，请求和解析成本高于普通条目。
- 首版只验证并匹配 `https://bgm.tv/`，没有验证其他 Bangumi 域名。
- 当前没有离线 HTML fixture 或自动化 DOM 单元测试；维护时应结合“已验证基线”在真实登录页面复查。
